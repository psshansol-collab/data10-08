## 요청 (2026-11-10 패들릿 댓글)

실적 수정 기능이 따로 있으니 일일 실적 입력란은 겹치는 기능으로 보인다 — 사용 편의성과 화면 간소화를 위해 입력란을 삭제해 달라는 요청입니다.

## 한 일

| 일일 실적 · 날짜 더하기 | 표 위에 날짜 칸 + 「날짜 더하기」. 누르면 그날 줄(목표 = 설정 기본값, 나머지 빈칸)을 만들고 바로 고치기 화면을 엶. 이미 있는 날짜면 그 줄을 엶. 저장하지 않고 「고치기 취소」로 닫으면 실제 대수 · 비고가 빈 줄은 지움. 그날 측정이 있으면 더하는 순간 측정 완성 대수가 채워짐 |
| 그대로 둔 것 | 표의 고치기 · 지우기, 엑셀 가져오기, 빈 양식 · 내려받기, 측정값 자동 반영 · 「측정값 쓰기 / 입력값 유지」 카드 |
| 문구 | 일일 실적 머리말, 대시보드 진행 순서, 빈 화면 안내, README 실행 방법 · 화면 표, 기획서(요구 · 기능 · 처리 흐름 · 와이어프레임) |
| `js/logic.js` | 순수 함수 `addDailyDay`(새 줄 · 있는 날짜 · 빈 날짜) · `dropBlankDay`(빈 줄만 지움) |

## 왜 이렇게 했나

- **입력란을 빼도 측정이 없는 날을 넣을 길은 남겨야 합니다.** 측정은 하루 중 일부 · 일부 날만 하는 경우가 많고, 엑셀은 하루치를 넣기에 번거롭습니다. 새 입력 화면을 만들면 요청 취지(겹침 제거)에 어긋나므로, 기존 「고치기」 화면을 그대로 다시 쓰고 줄을 만드는 단추 하나만 두었습니다.
- **빈 줄을 남기지 않습니다.** 날짜만 더하고 닫은 줄이 남으면 목표만 있는 날이 되어 달성률이 낮게 계산됩니다. 그래서 취소하면 실제 대수 · 비고가 빈 줄을 지웁니다(실제 0대는 값이라 남김).
- 인원 · 가용시간은 비워 두면 계산에서 설정 기본값을 씁니다(종전과 같음).

## 왜 이렇게 했나

- **기록에는 항목 id, 화면에는 이름.** 이름으로 저장하면 이름을 바꿀 때마다 기록을 고쳐 써야 하고 놓치면 계산에서 빠집니다. 기본 항목의 id 를 옛 구분 이름과 같게 두어 옛 기록은 고칠 것 없이 그대로 짝지어집니다. 목록에 없는 구분이 든 백업을 불러오면 지우지 않고 손실 항목으로 되살립니다.
- **계산은 분류로.** 「대기」를 「설비 대기」로 바꾸거나 새 손실 항목을 더해도 파레토 · 사이클타임이 그대로 동작합니다. 분류를 바꾸면(예: 대기 → 비작업) 계산이 따라갑니다.
- **글자 짝짓기는 지금 이름이 먼저, 저장된 기록은 id 가 먼저.** 두 항목의 이름을 맞바꿔도 지난 기록은 원래 항목에 남고, 새로 가져오는 엑셀 글자는 지금 이름대로 읽습니다.
- **일시정지는 구간을 나눠 기록합니다.** 멈춘 시간을 「일시정지」 구간으로 남기면 사이클타임 · 손실에서 빼기 쉽고 비작업 시간 분석에 그대로 쓰입니다. 화면 시계는 멈췄던 시간부터 이어 보이게 했습니다.
- **세팅은 기본으로 사이클타임에서 뺍니다.** 세팅을 사이클타임에 넣을지는 회사 기준에 따라 달라 확인란으로 두었습니다(기획서 확인 사항).

# 개발일지 — 2026-11-10 · 현장 측정 → 일일 실적 자동 반영 · 공정별 진행 현황 · 최종 기획서 v2.0

## 요청 (2026-11-10 패들릿)

현장 측정 결과가 일일 제작실적에 자동으로 반영되게 해 달라는 요청입니다(공정별 생산 CAPA 가 일 4대일 때 현장 측정 완료 수량이 일일 실적에 자동 기록). 실적 중복 입력을 줄이고, 공정별 사이클타임 · 계획 대비 실적 · 지연 공정을 쉽게 보려는 목적입니다.

## 한 일

| 곳 | 내용 |
|---|---|
| 공정 설정 | 공정마다 「하루 CAPA(대/일)」 칸(기본 4). 옛 자료에 없으면 4 로 읽음 |
| 현장 측정 · 스톱워치 | 「다음 대」 = 지금 대를 완료로 닫고 다음 번호로. 그날 마지막 대는 「완료하고 멈춤」, 끝내지 않은 대는 「멈춤(미완료)」. 구간에 `done`(대 완료) 표시를 남김 |

| 현장 측정 · 진행 현황 | 「공정별 진행 현황」(고른 측정일의 공정 × 완료/CAPA · 사이클타임 · 판정), 「날짜별 공정 진행」(최근 14 측정일 × 공정 표, 지연 칸 빨강) |
| 일일 실적 | 라인 완성 대수(마지막 공정 완료 수)를 그날 실제 대수로 자동 반영(「측정 반영」 표시). 그날 실적이 없으면 새로 만들고(목표 = 설정 기본값), 실제 대수가 비었으면 채움. **손으로 넣은 값과 다르면 덮어쓰지 않고** 「측정값과 손 입력이 다른 날」 카드에서 「측정값 쓰기 / 입력값 유지」를 고름. 표에 「측정」 칸 |

## 왜 이렇게 했나

- **완성 대수 = 마지막 공정 완료 수.** 앞 공정을 끝낸 대는 아직 라인을 나가지 않았습니다. 라인 출구(공정 설정 순서의 끝)에서 끝난 대만 그날 실적으로 봅니다. 공정별 완료 수는 진행 현황에 따로 보입니다.
- **완료는 「다음 대」로 정합니다.** 스톱워치는 구간을 바꿀 때마다 기록이 남아, 「작업 구간이 있다」만으로는 하는 중인 대도 완료로 셉니다. 「다음 대」 · 「완료하고 멈춤」으로 닫힌 대만 셉니다.
- **덮어쓰지 않습니다.** 측정은 하루 중 일부만 잴 때가 많습니다(가상 샘플도 하루 4대만 쟀고 실적은 7~10대). 측정값으로 손 입력을 덮으면 실적이 줄어드는 사고가 나므로, 다를 때는 고르게 했고 「입력값 유지」를 고르면 같은 측정값으로는 다시 묻지 않습니다.
- **지연 = 완료 < CAPA 또는 사이클타임 > 택트타임.** 측정이 없는 공정은 지연으로 보지 않고 「측정 없음」으로 둡니다.

## 계산을 이렇게 정한 이유

- **달성률은 합 ÷ 합.** 주·월 달성률을 날마다의 달성률 평균으로 내면 목표가 다른 날이 같은 무게가 됩니다. 실제 대수 합 ÷ 목표 대수 합으로 냅니다. 목표가 0인 날은 달성률을 비워 둡니다.
- **병목은 순작업 사이클타임으로 판정.** 측정해 보면 교정·사상 같은 뒤 공정의 「대기」가 큰데, 이는 병목(본용접) 때문에 생기는 결과입니다. 손실 포함 값으로 판정하면 기다리는 공정이 병목처럼 보여 엉뚱한 곳을 고치게 됩니다. 손실 포함 값은 그래프·표에 참고로만 둡니다.
- **측정 인원은 기록에서 셉니다.** 개선 전(본용접 2명)과 개선 후(3명)는 같은 공정이라도 인원이 달라서, 공정 설정의 인원 하나로 나누면 개선 전·후가 틀어집니다. 하루에 그 공정에 기록된 작업자 수의 평균을 쓰고, 측정이 없는 공정만 공정 설정의 인원을 씁니다. 배치가 다른 기간이 섞이면(소수로 나옴) 화면에서 기간을 나누라고 알립니다.
- **자동 배분은 「모두 1명 → 남은 인원을 그때그때 가장 긴 공정에」.** 「공수 ÷ 인원」의 최댓값을 줄이는 문제는 이 방법이 최선입니다. 테스트에서 9명 · 6공정의 모든 배분을 전수로 돌려 같은 값이 나오는 것을 확인했습니다. 개선 전 샘플 측정으로 돌리면 샘플의 실제 개선안(본용접 3명 · 사상·검사 2명)과 같은 답이 나옵니다.
- **대당 투입공수는 일일 실적에서.** (인원 × 가용시간)의 합 ÷ 실제 대수 — 손실까지 들어간 실제 값이라, 같은 인원으로 더 만들면 줄어듭니다. 단가 = 대당 투입공수 × 임률 + 기타 원가이고, 임률·원가는 모두 사용자가 넣습니다(회사 방식은 기획서 10장 4번).
- **엑셀 날짜·시각은 일련번호 그대로 읽습니다**(`cellDates` 끔). 엑셀 시각은 하루의 소수라서, Date 로 바꾸면 시간대 때문에 한 시간·하루가 밀릴 수 있습니다. 측정표는 일자를 첫 행에만 적는 일이 많아 빈 일자는 위 행 일자를 이어 씁니다.
- **스톱워치는 「누를 때마다 앞 구간을 닫고 새 구간을 엶」.** 현장에서 단추 하나만 누르면 되게 했고, 1초 안에 두 번 누른 것은 기록하지 않습니다. 측정 중인 구간은 저장소에 두어 화면을 닫거나 새로 고쳐도 이어집니다.
- **AI 프롬프트에서 작업자 이름을 가립니다(기본).** 작업자별 손실은 사람 평가로 읽힐 수 있고 이름은 개인정보라, 「작업자1」 별칭으로 바꾸고 대응표는 이 PC 에만 둡니다. 원가·절감액은 기본으로 빼고 켤 때만 넣습니다.
